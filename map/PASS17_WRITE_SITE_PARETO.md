# Pass 17 — sparse write organs: exact write-site placement Pareto curve

Date: 2026-08-10

Pass 13 showed that local reversible swaps plus even one defect-1 pinch can generate the full finite transformation monoid `T_n`.

Pass 17 asks the more physical question:

> **If irreversible/write hardware is scarce, where should it be placed, and how much local routing depth does each extra write site buy?**

This is still a finite toy compiler, not an AI architecture.

---

# 1. Physical-site convention

The earlier one-pinch oracle treated a directed merge such as

```text
2 -> 3
```

as one primitive site.

For this pass, a **physical write edge** is slightly stronger and more hardware-like: if edge `(i,i+1)` is writable, it may perform either directed defect-1 merge

```text
i -> i+1
```

or

```text
i+1 -> i.
```

Reversible adjacent swaps are available on every path edge.

Two schedule models are measured:

```text
SEQUENTIAL
    one local primitive per layer

PARALLEL
    any set of disjoint local swaps / allowed pinches may execute in one layer
```

For every placement set, exact BFS compiles **all `n^n` deterministic transformations** and reports shortest depths.

Script:

- `pinch_pareto_oracle.py`

---

# 2. Exact n=6 Pareto curve

For a path of six physical state locations, there are five possible write edges.

The exact best placements are:

| write edges available | best placement | worst sequential depth | mean sequential depth | worst parallel depth | mean parallel depth |
|---:|---|---:|---:|---:|---:|
| 1 | `(2,)` | 16 | 10.7733 | 11 | 6.7280 |
| 2 | `(1,3)` | 15 | 9.1024 | 8 | 5.5493 |
| 3 | `(0,2,4)` | 15 | 8.6603 | 7 | 4.9976 |
| 4 | `(0,1,3,4)` | 15 | 8.4515 | 7 | 4.7094 |
| 5 | `(0,1,2,3,4)` | 15 | 8.3078 | 6 | 4.4716 |

All rows generate the same full transformation monoid:

```text
|T_6| = 6^6 = 46656.
```

So the difference is **pure implementation cost**, not expressive power.

---

# 3. The first extra write organ buys most of the worst-case parallel improvement

With one optimally central write edge:

```text
parallel worst depth = 11.
```

With two well-spaced write edges:

```text
parallel worst depth = 8.
```

Adding every remaining edge as writable only reaches

```text
parallel worst depth = 6.
```

Thus in this tiny exact problem, going from one to two write sites captures

```text
3 / (11 - 6) = 60%
```

of the available worst-case parallel-depth improvement between the one-site and everywhere-writable endpoints.

Do not generalize that percentage beyond this toy.

The important qualitative shape is **diminishing returns**.

---

# 4. Placement itself matters

One write site does not have one universal cost.

For `n=6`, a single directed endpoint pinch in the earlier oracle gave worst depths around

```text
sequential 28
parallel   17
```

while moving the directed pinch to the central edge lowered them to roughly

```text
sequential 18
parallel   14.
```

Under the stronger bidirectional physical-edge convention of this pass, the optimal central site gives

```text
sequential 16
parallel   11.
```

So both **where** the irreversible primitive lives and **what local directions it supports** change the price substantially.

# 5. Smaller exact curves show the same broad tendency

For `n=4`:

| write sites | best edges | sequential max | parallel max |
|---:|---|---:|---:|
| 1 | `(1,)` | 7 | 6 |
| 2 | `(0,2)` | 6 | 5 |
| 3 | `(0,1,2)` | 6 | 4 |

For `n=5`:

| write sites | best edges | sequential max | parallel max |
|---:|---|---:|---:|
| 1 | `(1,)` | 12 | 9 |
| 2 | `(0,2)` | 10 | 7 |
| 3 | `(0,1,3)` | 10 | 6 |
| 4 | `(0,1,2,3)` | 10 | 5 |

The exact identity of the best set can depend on whether worst depth or mean depth is the tie-breaker. Treat the tables as compiler outputs, not closed-form placement theorems.

---

# 6. The geometry pattern is suggestive, but not yet a theorem

The best sparse placements tend to spread write sites across the path:

```text
n=6, k=1:     ..W..
n=6, k=2:     .W.W.
n=6, k=3:     W.W.W
```

This resembles a coverage/facility-location problem: reversible transport brings the relevant distinctions to a scarce irreversible site.

But shortest transformation words are more complicated than nearest-site distance alone. A transition may require multiple merges and permutations, and local operations can be parallelized only when supports are disjoint.

So do not replace the exact compiler with a simple graph-radius heuristic without testing it.

# 7. Prior-art boundary

Several mature fields sit directly around this result.

## Transformation semigroups on digraphs

Cameron, Castillo-Ramirez, Gadouleau & Mitchell (2017), *Lengths of words in transformation semigroups generated by digraphs*, study shortest words generated by graph-edge defect-1 idempotents.

They directly occupy:

```text
local rank-lowering generators
+ graph support
+ shortest transformation words.
```

KYY's toy library differs by mixing **free/available local permutations with a sparse subset of singular sites**, rather than making every generator a singular edge map.

## Reversible / nearest-neighbour circuit synthesis

Reversible-circuit and quantum compilation already price:

```text
nearest-neighbour routing
gate depth
ancillas
garbage outputs.
```

For example, Wille, Lye & Drechsler (2014) explicitly incorporate nearest-neighbour constraints at reversible-circuit synthesis time.

## Actuator placement

Network-control literature asks which limited actuator locations optimize controllability/energy criteria. Examples include Summers & Lygeros (2013) and Guo et al. (2019).

This is a close optimization analogy:

```text
number/location of control devices
        vs
network control cost.
```

But those objectives are continuous-state controllability/Gramian/energy metrics rather than exact finite transformation-word depth.

### Search status

This pass did **not** locate a standard named problem whose exact primitive library is:

```text
adjacent reversible permutations everywhere
+
one/few fixed local singular sites
+
optimize their placement for full or task-specific transformation word depth.
```

That is a search miss, **not a novelty claim**.

# 8. Why this matters to the physical lens

The picture can now be said very simply:

```text
mostly reversible body
        |
        | routes distinctions
        v
sparse write organs
        |
        | merge / overwrite when needed
        v
new behavioral state
```

The algebra says one write site is enough for expressivity.

The exact compiler says one badly placed write site can be expensive, while a small number of well-placed sites can remove much of that routing cost.

That is a genuine **geometry/resource statement** even though none of its ingredients are claimed new mathematics.

---

# 9. The next, harder question

Full `T_n` is a worst-case universe: it requires supporting every deterministic transition on `n` states.

A real task uses only a much smaller transition monoid `M_task`.

Therefore the next useful compiler problem is not

```text
best write sites for all of T_n
```

but

```text
best state realization + state placement + write-site placement
for only M_task.
```

This is where behavioral equivalence returns:

> **Can we choose an equivalent realization of the task so that its irreversible transitions naturally occur near a very small number of physical write sites, while its reversible transitions remain cheap local transport?**

That is the next valley to map before another learned architecture.
